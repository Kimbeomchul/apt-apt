# 시장조사 기반 UX 개선 실행계획

작성일: 2026-09-18. 상태: 아래는 조사 당시의 설계안이다. 사용자 실행 요청에 따라 핵심 UX·자금 일정·시나리오·보고서를 구현했다. 실제 반영 사항과 남은 작업은 [구현 기록](./UX_IMPLEMENTATION.md)을 기준으로 확인한다. 사용자 인터뷰·실측 개선율은 아직 없다.

## 1. 결론과 조사 범위

최우선 과제는 기능 수 확대가 아니라 **아파트를 발견하고, 내 돈으로 가능한지 이해하고, 후보를 비교하는 흐름**의 단순화다. 기존의 `내 자금 → 살 집 → 결과` 강제 순서는 수정한다. 기본 진입은 탐색으로 하고, 예산부터 알고 싶은 사람에게 별도 진입을 제공한다.

현재 저장소의 모바일 검증 캡처(`artifacts/mobile.png`)와 화면 구성·이벤트 코드(`index.html`, `src/app.js`, `src/household-ui.js`)를 검토했다. 경쟁 서비스는 공개 웹과 공식 앱 소개를 조사했다. 로그인 후 앱 전 과정을 직접 테스트하거나 사용자 인터뷰를 수행한 것은 아니다. 아래 불편의 원인은 화면 관찰에 따른 가설이며, 개선 효과·시장점유율을 측정한 결과가 아니다.

## 4. 제안하는 화면 흐름

기본: **아파트 탐색 → 단지 상세 → 내 예산 적용 → 후보 저장·비교**.

선택 진입: **내 예산 알아보기 → 기본 자금 → 해당하는 추가 조건 → 결과 적용 → 아파트 탐색**. 기존 3단계 계획은 이 선택 흐름 안에 한정한다.

- 탐색: 지역/단지 검색, 가격대, 면적, 결과 목록. `6억 미만 / 6~8억 / 8~11억 / 11~15억` 유지. 중복 집계를 피하도록 경계는 6 이상~8 미만, 8 이상~11 미만, 11 이상~15 이하로 정의하고 15억 초과·가격 미확인도 전체에서 접근 가능하게 한다.
- 자금: `나 혼자 / 부부 합산`, 내 소득·돈과 배우자 소득·돈 구분. 현금에 이미 포함된 증여인지 명시해 중복 합산 방지. 증여세와 세후 가용금액, 자금 수령 예정일을 분리한다.
- 금액 입력: `30,000만원 = 3억원`을 함께 표시하고 숫자 키패드·천 단위 구분 제공. 예시값은 실제 입력과 명확히 분리한다.
- 결과: 여유를 둔 예산, 선택 단지의 부족 자금, 월 상환액을 우선 표시. 최대 예산은 가정과 함께 펼쳐 본다. 계산 가능·추가 확인·자금 부족을 문구와 아이콘으로 구분한다.
- 상세: `가격·거래 / 내 자금 / 단지 정보`로 정리. 겹치는 3·6·12개월 집계를 월별 추세처럼 표현하지 않는다. 출처·표본 수·기준일은 쉽게 확인할 수 있도록 유지한다.
- 비교: 최대 3개, 같은 면적·기간 기준으로 가격·부족 자금·월 상환액·자료 신뢰도를 비교. 이후 인쇄/PDF와 잔금 일정으로 확장한다.
- 저장: 최근 검색·관심 단지·비교 후보는 복원. 민감한 자금 프로필은 `이 기기에 저장`을 직접 선택한 경우에만 보관하고 삭제 기능 제공. 공유 URL에는 개인 금융 값을 넣지 않는다.
- 시각 스타일: 밝은 배경·짙은 남색 본문·청록 강조색 유지, 경고는 필요한 경우만 사용. 색만으로 가능 여부를 전달하지 않는다. 터치 영역 44px 이상을 설계 목표로 삼고 대비·키보드 포커스·스크린리더 이름을 검사한다.

## 5. 실행 순서와 기존 계획 통합

아래는 작업 묶음 순서이며 고정 일정 약속이 아니다. 단계마다 검증 후 다음으로 진행한다.

1. **현 상태 기준 측정과 모바일 시안**: 탐색 우선 화면·자금 설정·0건 화면·상세 복귀를 프로토타입으로 만든다. 기존 사이트와 동일 과제로 비교한다.
2. **P0 흐름 개선**: 첫 화면 재구성, 선택형 자금 설정, 임시 입력/적용 모델, 가독성, 0건 복구. 기존 계산 엔진은 유지하면서 노출·상태 처리를 분리한다.
3. **P1 후보 결정 개선**: 필터 통합, 카드 단순화, 뒤로 가기·저장 복원, 비교 화면. 데이터 범위와 갱신일 표시도 함께 정리한다.
4. **기존 금융 고도화 연결**: 계약금·중도금·잔금 시점별 자금표, 금리·소득 변동 시나리오, 비교 인쇄/PDF. 부부·증여 자금의 실제 이용 가능 날짜를 반영한다.
5. **데이터·확장**: 갱신 자동화와 취소·정정 거래 품질 관리, 공식 근거가 검증된 정책 상품, 생활권 정보. 지도는 좌표 품질·지도 제공 조건·성능을 검토하고 탐색 개선 효과를 확인한 뒤 착수한다.

당장 후순위: AI 채팅 추천, 임의 종합점수 추가, 커뮤니티, 로그인 강제, 전국 확장. 현재 탐색·입력의 불편을 해결한다는 근거가 먼저 필요하다.

구현 영향 범위: `index.html`과 `src/app.js`의 탐색/설정 상태 분리, `src/household-ui.js`의 조건부 질문, `src/theme.css`의 정보 위계, `src/explore.js`·필터의 복원 상태. 계산식 변경은 별도 작업으로 격리하고 기존 금융·증여 테스트를 유지한다.

## 6. 검증 계획과 성공 기준

실수요자 5~8명으로 진행하는 형성적 사용성 테스트를 제안한다. 혼자/부부, 증여 있음/없음, 기존 대출 또는 상환 경험이 있는 경우를 포함한다. 모집·실험은 아직 하지 않았다. 소규모 테스트 결과로 시장 전체 개선율을 주장하지 않는다.

과제: ① 원하는 지역의 6~8억 후보 찾기 ② 부부·증여 조건으로 예산 적용하기 ③ 최근 상환 이력을 입력하고 결과 이유 설명하기 ④ 3개 후보 비교 후 목록 복귀하기 ⑤ 0건에서 조건을 완화하기.

| 지표 | 측정 방법 | 제안 목표(현재 실측값 아님) |
| --- | --- | --- |
| 첫 후보 상세까지 시간 | 같은 기기·같은 과제의 기존/시안 비교 | 중앙값 30초 이내, 기존 대비 단축 |
| 기본 예산 설정 시간 | 설명자 개입 없이 시작부터 적용까지 | 중앙값 2분 이내 |
| 핵심 과제 완료율 | 도움 없이 완료한 사람 수/참여자 수를 함께 보고 | 80% 이상 |
| 결과 이해 | 예산, 부족금, 확인 필요 이유를 본인 말로 설명 | 80% 이상 |
| 0건 복구 | 조건을 수정해 다시 후보를 찾는 시간 | 15초 이내 |
| UI 안정성 | 화면 폭·확대·키보드·접기/펼치기·뒤로 가기 검증 | 주요 버튼 가림·가로 넘침·입력 유실 0건 |

배포 후 측정은 검색 시작→상세 열기→예산 적용→비교 진입 등 사건 중심으로 설계한다. 실제 소득·현금·증여액·검색 원문을 분석 로그로 전송하지 않는다. 표본이 적으면 A/B 통계 결론 대신 관찰 테스트를 반복한다. 체류시간 증가는 성공 지표로 삼지 않는다.

첫 릴리스 범위는 **탐색 우선 진입 + 선택형 자금 설정 + 0건 복구 + 카드/글자 위계 정리**로 제한한다. 완료 후 사용자 검증을 통해 다음 묶음의 우선순위를 다시 정한다.
